

Key design decisions:

\- \*\*Stock reservation model:\*\* stock is decremented at order creation (not payment), with a 15-minute expiry window if payment isn't completed.

\- \*\*Price snapshotting:\*\* each order item stores `price\_paise\_at\_purchase`, so price changes never affect historical orders.

\- \*\*Soft deletes:\*\* products are deactivated (`is\_active: false`), never hard-deleted, so historical orders always resolve correctly.

\- \*\*Idempotent payments:\*\* duplicate payment requests with the same idempotency key return the original result instead of creating a second payment.

\- \*\*Row locking on checkout:\*\* `SELECT ... FOR UPDATE` on product stock during order creation prevents race conditions when two users buy the same item simultaneously.



\---



\## Business Rules



\- Single currency (INR), stored in paise (integer) to avoid floating-point errors.

\- Two roles: customer and admin.

\- Orders expire 15 minutes after creation if unpaid.

\- Payments are simulated (no real gateway), with an 80% success / 20% decline rate to test both outcomes.

\## Test Suite



Postman collection organized into 7 folders:



\- \*\*Authentication\*\* — signup, login

\- \*\*Products\*\* — CRUD, data-driven tests (CSV-based)

\- \*\*Cart\*\* — add/remove items, stock validation

\- \*\*Orders\*\* — order creation, transactional integrity

\- \*\*Payments\*\* — simulated payment, idempotency

\- \*\*Negative \& Boundary Tests\*\* — 5 tests covering missing auth, invalid IDs, stock limits, duplicate payments, wrong credentials

\- \*\*Regression Workflows\*\* — full end-to-end flow (signup → login → browse → cart → order → pay → verify), runs reliably regardless of simulated payment outcome

\- \*\*Security Tests\*\* — BOLA (Broken Object Level Authorization) check: verifies User B cannot access User A's orders



24 documented test cases in `docs/test-plan.md` with preconditions, test data, expected/actual results, and priority.



\### Running the tests locally



```bash

\# 1. Start the app and database

docker compose -f docker/docker-compose.yml up -d --build



\# 2. Seed test data

docker exec ecommerce\_app python -m scripts.seed\_data



\# 3. Run the Postman suite via Newman

newman run tests/postman/collections/ecommerce-api-collection.json \\

&#x20; -e tests/postman/environments/local-dev-environment.json \\

&#x20; --reporters cli,htmlextra \\

&#x20; --reporter-htmlextra-export reports/newman-report.html

```



\### Load testing



```bash

k6 run scripts/load\_test.js

```

\## CI/CD Pipeline



A Jenkins pipeline (`ci/Jenkinsfile`) runs on every push:



1\. Checkout code from GitHub

2\. Build and start the app + database via Docker Compose

3\. Wait for health check

4\. Seed test data

5\. Run the full Newman test suite

6\. Publish an HTML test report

7\. Tear down containers (runs even if a prior stage fails)

\## Bugs Found and Fixed During Testing



A few examples of real issues caught while building the automated suite (full documentation of process in commit history):



\- \*\*Flaky regression test:\*\* a test asserted order status was always `"paid"`, but the simulated payment gateway has a 20% decline rate — fixed by asserting either valid outcome (`paid` or `pending\_payment`).

\- \*\*Stale test data:\*\* repeated test runs depleted product stock, causing later runs to fail with `409 Conflict` — fixed with a seed script that resets stock before each run.

\- \*\*PostgreSQL 18 volume mount change:\*\* Docker image required a different volume mount path than earlier Postgres versions, causing silent container restarts — diagnosed via `docker logs`.

\- \*\*Silent Alembic migration:\*\* a migration ran "successfully" but created no tables, because the model wasn't imported in `env.py` — caught by directly verifying table existence in the database rather than trusting the migration log.
